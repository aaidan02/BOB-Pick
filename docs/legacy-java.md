# BOB Pick — 기존 Java 버전

CSV의 전체 메뉴에서 조건에 맞는 메뉴를 찾아 음식점과 메뉴를 추천하고, 같은 음식점의 위도·경도로 네이버 지도에 마커를 표시합니다. 가격·음식 종류·음식 형태와 방문 날짜·시각을 조합해 필터링합니다. 가격·종류·형태는 기본값이 전체이며, 영업시간은 한국 현재 날짜·시각을 기본값으로 사용합니다.

**기본 설정 그대로 뽑으면 기존처럼 음식점 한 곳을 추천합니다.** 가격·음식 종류·음식 형태를 입력하거나 방문 날짜·시각을 직접 지정하면, 조건에 맞는 서로 다른 음식점을 최대 세 곳까지 보여 줍니다. 기본으로 적용되는 현재 시각과 영업시간 적용 해제만으로는 세 곳 추천으로 바뀌지 않습니다.

조건 검색 결과의 **마음에 들어요**를 체크하면 해당 카드의 가게·메뉴·가격을 현재 자리에 고정합니다. **새로고침**은 체크하지 않은 카드만 다시 추첨하며, 고정한 가게와 중복되지 않습니다. 새 후보가 충분하면 직전의 고정하지 않은 가게도 제외하고, 후보가 부족하면 기존 후보를 다시 사용할 수 있습니다. 후보가 한두 곳뿐이면 중복으로 세 칸을 채우지 않고 해당 가게만 표시합니다. 세 곳을 모두 고정하면 새로고침이 비활성화되고, 체크를 해제하면 다시 뽑을 수 있습니다.

수동 결과를 표시 중에 가격·종류·형태·방문 일시를 직접 변경하거나 조건을 초기화하면 해당 추천과 고정도 초기화합니다. 현재 시각의 자동 갱신은 추천 카드·고정 상태·지도 마커를 지우지 않습니다. 고정은 현재 화면에서 사용하는 상태이며 브라우저 자체 새로고침(F5) 후에는 유지하지 않습니다. 지도에는 표시 중인 추천 가게들의 마커를 함께 표시하고 각 카드에서 해당 가게의 네이버 길찾기를 열 수 있습니다.

현재 웹 화면은 첨부된 `밥픽_개발계획서_최종_수정본.pptx` 7페이지의 화면 시안에 맞춰 주황색 포인트, 크림색 배경, 둥근 카드와 밥그릇 캐릭터를 적용했습니다. CSS와 SVG가 `FoodPickerWeb.java`에 포함되어 별도 이미지·스타일 파일 없이 실행합니다. 화면에는 검색 조건, 메뉴·가격, 음식점 정보와 지도만 표시하고, CSV 기준·영업 상태·실시간 여부 안내 문구는 표시하지 않습니다.

## 수동 검색과 AI 채팅

**수동 검색**에서 가격·음식 종류·음식 형태·방문 일시를 직접 입력하고 검색합니다. 이 영역의 버튼은 항상 CSV 조건 검색과 랜덤 추첨만 수행하며 Gemini를 호출하지 않습니다. 기본 설정 그대로면 한 곳, 조건을 입력하면 최대 세 곳을 추천합니다.

**AI 채팅**은 별도 영역입니다. “만 원 이하로 따뜻한 국물 요리 먹고 싶어”처럼 입력하면 Gemini가 대화를 읽고 CSV 후보 중 최대 세 가게와 메뉴를 고릅니다. 수동 검색창에 입력한 값은 채팅에 전달하지 않으며, 채팅의 방문 일시가 없으면 한국 현재 시각을 적용합니다. 최근 대화를 함께 보내므로 후속 요청도 이어갈 수 있습니다.

두 영역에는 각각 추천 버튼·오류 표시·초기화가 있습니다. 수동 조건 변경·초기화는 AI 대화를 지우지 않고, 대화 초기화는 수동 검색 결과를 지우지 않습니다. 아래 메뉴 카드와 지도는 가장 최근에 실행한 검색의 결과를 표시합니다. AI 대기 중에도 수동 검색을 할 수 있으며 늦게 도착한 AI 응답은 최신 수동 결과를 덮어쓰지 않습니다.

현재 표시된 가게에 **마음에 들어요**를 체크하면 같은 영역에서 다시 뽑을 때 고정합니다. 수동 결과는 수동 **새로고침**, AI 결과는 채팅 영역의 **다시 추천받기**를 사용합니다. 다른 영역으로 검색을 전환하거나 같은 영역의 검색 조건을 변경하면 고정도 새 결과에 맞춰 초기화됩니다. 현재 시각 자동 갱신은 이미 고른 카드·고정을 지우지 않고 추가 AI 호출도 만들지 않습니다.

## 결과 이동과 완료 알림

수동 검색이나 AI 추천에서 실제 메뉴 카드가 나오면 결과 영역으로 자동 스크롤합니다. AI 추천 성공 시 우측 하단에 초록색 **성공!** 알림을 띄우고 3초 뒤 숨깁니다. 연속 성공은 마지막 완료 시점부터 다시 3초를 셉니다. 오류·추가 질문·빈 추천에는 성공 알림이나 결과 스크롤을 적용하지 않습니다. 늦은 AI 완료는 최신 수동 결과나 스크롤을 바꾸지 않습니다. 운영체제의 동작 줄이기 설정에서는 부드러운 스크롤·알림 등장 효과를 생략합니다.

## Gemini 연결과 응답 시간

Java 서버는 먼저 채팅을 가격·종류·형태·메뉴/상호 키워드·방문 일시로 해석하고, 다음 요청에서 그 조건을 만족하는 CSV 후보를 Gemini가 선택하게 합니다. 선택 ID·메뉴 인덱스·중복·고정 제외를 서버에서 확인하며 표시할 가게명·메뉴명·가격·주소·좌표는 CSV에서 가져옵니다. 모호한 시간이나 자료로 보장할 수 없는 요청은 채팅으로 추가 확인합니다.

이전 구현은 요청당 35초, 브라우저는 전체 80초를 기다렸습니다. 두 API 요청이 순서대로 실행되므로 70초 안팎의 지연에서 어느 단계가 멈췄는지 알기 어려웠습니다. 현재 구현은 다음을 적용합니다.

- 기본 모델 `gemini-3.5-flash-lite`, Flash-Lite의 최소 추론 설정.
- 후보를 일부로 자르지 않고 모든 후보를 배열 형식으로 전달해 반복 필드명을 줄임.
- 기본 요청당 60초, 브라우저 제한은 서버의 두 요청 제한 합계에 10초를 더해 일치시킴.
- `GEMINI_TIMEOUT_SECONDS`로 요청당 15~120초 설정 가능.
- 터미널에 조건 해석/메뉴 선택 단계, 모델, 요청 크기, HTTP 상태, 소요 시간을 기록. API 키와 대화 원문은 기록하지 않음.
- DNS·보안 연결·연결 시간 초과·응답 시간 초과·키·모델·사용량 오류를 구분.

Gemini API 키는 **프로그램을 실행할 때마다 터미널에서 새로 입력**합니다. 키 입력 문구가 뜬 뒤 **Ctrl+Shift+V 또는 터미널의 붙여넣기**를 사용하고 Enter를 누릅니다. 일반 터미널에서는 입력값이 보이지 않아도 정상이며, 키는 해당 Java 프로세스의 메모리에서만 사용합니다. 일부 터미널의 붙여넣기 제어 문자는 입력에서 제거합니다. Enter 후 입력값이 있으면 **API 키 입력 완료**, 비어 있으면 **API 키 미입력: 수동 검색만 사용합니다**를 표시해 숨김 입력 여부를 확인할 수 있습니다. 이 표시는 입력 여부만 확인합니다. 파일·CSV·브라우저 저장소에 저장하지 않고, 기존 `GEMINI_API_KEY` 환경변수도 읽지 않습니다. 빈 Enter로 건너뛰면 수동 검색만 사용할 수 있습니다. VS Code에서는 출력/디버그 콘솔 대신 터미널에서 실행하세요.

모델·대기시간처럼 비밀이 아닌 설정만 필요한 경우 환경변수로 바꿀 수 있습니다. API 키를 명령에 넣을 필요는 없습니다.

```powershell
$env:GEMINI_MODEL = "gemini-3.5-flash-lite"
$env:GEMINI_TIMEOUT_SECONDS = "60"
```

이전에 터미널에 `GEMINI_MODEL=gemini-3.8-flash`를 설정했다면 새 모델 설정을 실행하고 서버를 다시 시작해야 합니다. 별도 모델을 사용하려면 계정에서 지원하는 모델 ID를 설정합니다.

컴파일 후 `java -cp build GeminiFoodRecommender`로 작은 JSON 응답만 요청하는 연결 확인을 실행할 수 있습니다. 일반 실행 방식으로 현재 폴더에 컴파일했다면 `java -cp "." GeminiFoodRecommender`입니다. 이 명령도 실행 시 키를 새로 입력받으며, 실제 키·네트워크·모델 사용 권한을 분리해서 확인하고 CSV는 전송하지 않습니다. 출력의 마지막 줄이 **Gemini 연결 성공**인지 확인합니다.

연결 확인이 성공하고 추천만 실패하면 터미널의 `[AI] 단계=조건 해석` 또는 `[AI] 단계=메뉴 선택`과 HTTP 상태·소요 시간을 확인합니다. 실제 서비스 응답은 사용자 PC에서 확인해야 하며 로컬 응답 대역 검증과 구분합니다.

외부 Java 라이브러리는 필요하지 않습니다. 대화와 후보 메뉴 데이터는 Gemini API로 전송됩니다. 참고: [Gemini API 키](https://ai.google.dev/gemini-api/docs/generate-content/api-key), [구조화 응답](https://ai.google.dev/gemini-api/docs/generate-content/structured-output), [Gemini 3.5 Flash-Lite](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite).


## 추천 조건

현재 시각을 15초마다 확인하고 분·날짜가 바뀌면 입력 시각과 후보 수를 갱신합니다. 이 자동 갱신은 이미 뽑은 메뉴·가격·지도 마커를 지우거나 대기 중인 추천 요청을 취소하지 않습니다. 사용자가 가격·종류·형태·방문 일시를 직접 바꾸거나 초기화할 때는 이전 결과를 지우고 새 조건을 적용합니다.

- 가격: 최소·최대 금액을 원 단위로 지정합니다. 한쪽만 입력할 수 있고, 모두 비우면 가격 제한이 없습니다. 경계 금액을 포함합니다.
- 음식 종류: CSV의 `음식 종류` 열을 직접 사용합니다. 현재 한식, 양식, 중식, 일식, 아시안, 분식, 패스트푸드, 치킨, 카페·디저트, 야식, 기타가 있으며 기본값은 **랜덤 (전체)**입니다.
- 음식 형태: CSV의 `음식 형태` 열을 직접 사용합니다. 현재 면, 밥, 튀김, 국·탕·찌개, 구이, 찜·삶음, 볶음, 빵, 디저트, 음료, 회·생식, 미분류가 있으며 기본값은 **랜덤 (전체)**입니다.
- 조건을 만족하는 메뉴가 있는 음식점 중 균등 추첨하고, 그 가게에서 맞는 메뉴 한 개를 뽑습니다. 메뉴 수가 많은 가게에 더 높은 확률을 주지 않습니다. 후보가 둘 이상이면 바로 직전 음식점을 제외합니다. 가게가 한 곳이어도 맞는 메뉴가 여러 개면 직전 메뉴를 제외하고 다시 뽑을 수 있습니다.
- **조건 초기화**는 가격·종류·형태를 전체로, 방문 일시는 한국 현재 날짜·시각으로 되돌립니다. 영업시간 적용을 끄면 시간 미확인 식당까지 포함합니다. 조건을 바꾸면 이전 추천과 마커를 지우고 후보 수를 갱신합니다.

`메뉴한글명`의 모든 항목과 같은 위치의 `메뉴금액`을 앞에서부터 차례로 연결합니다. 가격 항목이 부족하면 뒤쪽 메뉴는 ‘가격 표시 없음’으로 표시하고, 메뉴보다 많은 가격 항목은 사용하지 않습니다. 쉼표·세미콜론 구분, 따옴표, 괄호 안의 쉼표를 처리합니다. 사이즈별 메뉴와 가격도 개별 항목으로 검색합니다. 같은 이름·가격의 중복 항목은 한 번만 사용합니다. 추천 메뉴와 그 메뉴의 가격을 함께 표시하고, 해당 가게의 조건에 맞는 전체 메뉴 목록도 보여줍니다.

`가격 7,000원`·`업주문의8500`처럼 설명이 붙은 가격은 금액 하나가 명확할 때 숫자로 읽습니다. `변동가격(업주문의)26000`처럼 ‘변동’이 포함된 항목은 숫자가 있어도 **변동가격**으로 표시하며 고정 금액으로 사용하지 않습니다. 변동가격·금액 누락·여러 금액이 섞인 항목은 가격 조건을 지정하면 제외합니다. 이 처리는 CSV 원문을 수정하지 않으며 수동 검색과 AI 추천에 함께 적용됩니다.

가격이 없거나 0으로 기록된 메뉴는 가격 조건을 비웠을 때 포함하고, 가격 조건을 지정하면 제외합니다. 가게의 음식 종류와 형태는 CSV 등록값으로 판정하며 `업종정보`를 검색에 사용하지 않습니다. `면 | 밥 | 구이`처럼 `|`로 나눈 값은 각각 선택할 수 있고, `카페·디저트`와 `국·탕·찌개`는 각각 하나의 값입니다. 빈 셀은 랜덤에는 포함되지만 특정 종류·형태에는 일치하지 않습니다. 선택 목록도 CSV에 실제로 있는 값으로 만들므로 새 값을 저장한 뒤 서버를 재시작하면 반영됩니다.

`음식 형태`는 가게 전체의 형태를 요약한 값이므로, 개별 메뉴의 형태는 CSV 작성 때와 같은 메뉴명 규칙으로 연결합니다. 가게에 등록된 형태 안에서만 연결하며, 메뉴가 한 개여도 이름으로 확인되지 않은 형태를 일괄 적용하지 않습니다. 해당 형태를 확인할 수 없는 항목은 형태 조건 추천에서 제외합니다. `미분류`는 이름으로 형태를 알 수 없는 메뉴에 대응합니다. 음식 종류는 기존 CSV 값을 그대로 사용합니다.

형태와 가격은 **같은 메뉴가 모두 만족**해야 합니다. 예를 들어 삼겹살 12,000원·냉면 5,000원·공깃밥 1,000원인 가게에서 `면 / 6,000원 이하`를 선택하면 냉면 5,000원을 보여줍니다. `면 / 1,000원 이하`에는 포함되지 않습니다. 대표메뉴는 조건이나 표시 메뉴를 결정하지 않으며 원본 정보에만 남깁니다. 전체 메뉴가 없는 가게는 가격·형태 조건에서 제외하고, 조건을 비우면 음식점과 위치를 보여줍니다. 종류·형태 필터는 CSV의 값을 변경하지 않습니다.

## VS Code에서 실행

`RandomFoodPicker.java`와 CSV가 있는 폴더에 `FoodPickerWeb.java`, `BusinessHours.java`, `GeminiFoodRecommender.java`를 저장합니다. 웹 화면과 서버는 `FoodPickerWeb.java`에 포함되며 CSV 읽기와 추첨은 `RandomFoodPicker.java`, 영업시간 판정은 `BusinessHours.java`를 사용합니다. 현재 Java 코드에는 폐업 확정 행을 제외하는 처리가 포함되어 있습니다.

`FoodPickerWeb.java`는 서버 시작 시 `최종대조판정`이 `폐업`인 행을 제외하고, CSV에도 남은 행만 저장합니다. 기존 `RandomFoodPicker.java`를 수정하지 않은 경우에도 적용됩니다. 미확정·미확인과 다른 열의 값, 행 순서, CP949 인코딩은 유지하며 CSV의 따옴표와 줄바꿈 형식은 저장 과정에서 정리됩니다.

1. VS Code의 **파일 → 폴더 열기**에서 `C:\Users\COMPUTER\Desktop\bob-pick-test`를 엽니다.
2. 해당 폴더에 `FoodPickerWeb.java`, `BusinessHours.java`, `GeminiFoodRecommender.java`를 UTF-8로 저장합니다. 기존 Java와 `관내 음식점 텍스트 데이터셋_둔산동_재검토_2.csv`도 같은 폴더에 있어야 합니다.
3. **터미널 → 새 터미널**을 열고 아래 명령을 실행합니다. JDK 17 이상이 필요합니다.

```powershell
chcp 65001 > $null
$bobPickUtf8 = New-Object System.Text.UTF8Encoding -ArgumentList $false
[Console]::InputEncoding = $bobPickUtf8
[Console]::OutputEncoding = $bobPickUtf8
$OutputEncoding = $bobPickUtf8
javac -encoding UTF-8 .\RandomFoodPicker.java .\BusinessHours.java .\GeminiFoodRecommender.java .\FoodPickerWeb.java
java -cp "." FoodPickerWeb
```

위 명령은 Java의 UTF-8 출력과 PowerShell 터미널의 인코딩을 맞춥니다. `javac -encoding UTF-8`은 소스 파일을 읽는 설정이며 터미널 출력 설정과 별개입니다. CSV는 기존 CP949/MS949를 유지합니다. 새 터미널에서는 인코딩 설정도 다시 실행합니다.

4. 브라우저에서 [http://localhost:8000](http://localhost:8000)을 엽니다. 서버 종료는 터미널에서 `Ctrl+C`입니다.

`javac`를 찾을 수 없다면 JDK를 설치하고 PATH에 JDK의 `bin`을 추가한 다음 VS Code를 다시 엽니다. 이 실행 방식은 VS Code 터미널을 사용하며 별도 확장을 요구하지 않습니다. 지도는 기존 HTML의 Client ID를 사용합니다.

## 휴대폰 접속·위치 확인

휴대폰의 `localhost`는 PC가 아닌 휴대폰 자신을 뜻합니다. 현재 Java 서버는 PC 내부에서만 받으므로 휴대폰에서 `localhost:8000`이나 PC의 Wi-Fi IP로 직접 접속할 수 없습니다. 휴대폰의 일반 `http://PC주소` 접속은 브라우저 위치 조회에 필요한 보안 연결도 충족하지 않습니다.

위치 테스트에는 임시 HTTPS 연결을 사용합니다. PC의 Java 서버를 실행해 둔 뒤, 같은 프로젝트 폴더의 **새 PowerShell 터미널**에서 Cloudflare 공식 실행 파일을 받고 실행합니다.

```powershell
Invoke-WebRequest -Uri "https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-windows-amd64.exe" -OutFile .\cloudflared.exe
.\cloudflared.exe tunnel --url http://127.0.0.1:8000
```

출력된 `https://...trycloudflare.com` 주소를 휴대폰 브라우저에서 엽니다. 추천 화면은 해당 주소 그대로, 위치 테스트는 뒤에 **`/location-test`**를 붙여 접속합니다. 위치 테스트의 **현재 위치 확인**을 누르고 휴대폰·브라우저에서 위치 사용을 허용하면 위도·경도·정확도가 표시됩니다. Java 서버와 터널 터미널은 모두 켜 둡니다.

이 주소는 인터넷에서 접속 가능한 임시 공개 주소입니다. 터널 터미널에서 `Ctrl+C`를 누르면 접속이 종료됩니다. 여기서는 터널을 직접 생성하거나 서비스를 공개 배포하지 않았으며, PC에서 위 명령을 실행할 때 주소가 발급됩니다. 참고: [Cloudflare Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/), [공식 Windows 다운로드](https://developers.cloudflare.com/tunnel/downloads/), [브라우저 위치 API의 HTTPS·권한 요건](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/getCurrentPosition).

`/location-test`는 별도 진단 화면입니다. 버튼을 눌렀을 때만 위치를 조회하고 브라우저 화면에 표시하며 서버에 전송하거나 길찾기 출발지에 자동 입력하지 않습니다. GPS·Wi-Fi 등 측정 출처는 웹에서 구분할 수 없습니다. GPS 센서를 사용했다고 판정하거나 정확도로 GPS라고 추정하지 않습니다. 테스트 페이지는 네이버 지도 SDK를 사용하지 않아 Maps Client ID의 도메인 등록과 관계없이 위치 조회를 확인할 수 있습니다. 임시 주소에서 추천 화면의 지도까지 표시하려면 네이버 Maps 콘솔에 해당 HTTPS 주소를 등록해야 합니다.

## 네이버 지도 설정

추천 결과의 **네이버 길찾기**를 누르면 `/directions?restaurant=음식점ID`를 새 탭에서 열고, CSV의 음식점 위도·경도와 이름을 도착지로 넣어 네이버 웹 길찾기의 대중교통 화면으로 바로 이동합니다. 출발지는 비워 두므로 네이버 지도에서 직접 입력합니다. 자동차·도보 등도 네이버 지도에서 변경할 수 있습니다. 기존 추천 화면은 유지합니다.

GPS가 아니면 출발지를 자동 설정하지 않는다는 요청에 따라, GPS 출처를 증명할 수 없는 브라우저 위치 정보는 길찾기에 사용하지 않습니다. 웹 API는 GPS·Wi-Fi·네트워크 측정 출처를 구분해 주지 않으므로 추천·길찾기 화면은 위치를 요청하거나 출발지를 자동 입력하지 않습니다. 별도 `/location-test` 진단 화면에서 버튼을 눌렀을 때만 테스트용 위치를 조회합니다. 정확도나 기기 종류로 GPS라고 추정하지 않습니다. 음식점 좌표가 없으면 음식점 검색 화면으로 연결합니다.

웹 길찾기 좌표는 WGS84에서 EPSG:3857로 변환해 전달합니다. 참고: [네이버 웹 길찾기 연동 구현 자료](https://github.com/Scripter36/SeoulPublicTransportAnalyzer#네이버-지도), [네이버 공식 출발지·도착지 설정 안내](https://help.naver.com/service/5637/contents/8301?osType=PC). 앱 호출용 `nmap://` 스킴과 구분해 PC의 HTTPS 길찾기 화면을 사용합니다.

첨부된 HTML의 Maps Client ID를 기본값으로 유지했습니다. 해당 ID가 속한 Maps 콘솔에서 **Dynamic Map** 사용과 Web 서비스 URL **`http://localhost:8000`** 등록을 확인하세요. 다른 주소나 포트로 접속하면 그 주소도 등록해야 합니다.

본인 Client ID로 바꾸려면 명령 프롬프트에서 다음과 같이 실행합니다.

```bat
set "NAVER_MAP_CLIENT_ID=본인_Maps_Client_ID"
start.bat
```

화면에 사용하는 ID는 공개용 Maps Client ID입니다. Client Secret은 필요하지 않습니다. 첨부된 CSV의 모든 음식점에 좌표가 있으므로 Geocoding API나 별도의 음식점 검색 API 없이 마커를 표시합니다. API 로딩·인증 실패 시에도 음식점 추첨과 **네이버 길찾기**는 사용할 수 있습니다.

## 포함된 데이터와 추첨 기준

- 기본 파일: `관내 음식점 텍스트 데이터셋_둔산동_재검토_2.csv` (CP949/MS949), 음식점 **808곳**, 48개 열. 기존 45개 열에 `음식 종류`, `음식 형태`, `영업 시간대`를 추가했습니다.
- 음식점을 동일 확률로 뽑고, 해당 음식점의 전체 메뉴 중 조건에 맞는 메뉴와 가격을 표시합니다. 음식점이 여러 곳이면 두 번째부터는 직전 한 곳을 제외합니다. A → B → A는 가능합니다.
- **`최종대조판정`이 정확히 `폐업`인 226곳을 CSV에서 삭제했습니다.** 남은 데이터는 영업/정상 383곳, 미확정 425곳입니다. 남긴 행의 모든 값과 순서, CP949 인코딩과 줄바꿈을 보존했습니다.
- Java에서 CSV를 읽을 때도 `최종대조판정`의 앞뒤 공백을 제외한 값이 `폐업`인 행만 제외합니다. `미확정`, `미확인`, 빈 값, `폐업 여부 미확인`은 유지하며, 다른 열의 폐업 문구로 삭제하지 않습니다. 최종 판정 열이 없는 CSV도 임의로 삭제하지 않습니다. CSV 행 정리 단계에서는 가격·업종으로 삭제하지 않습니다.
- 대표메뉴가 비어 있어도 전체 메뉴가 있으면 해당 메뉴를 추천합니다. 전체 메뉴도 없으면 가격·형태 조건을 비웠을 때 음식점과 위치를 보여주고 **메뉴 정보가 없어요**로 안내합니다.
- 결과에 메뉴·가격·음식 종류·형태와 `주소`, `상세주소`, `전화번호`, `운영시간정보`를 표시합니다. 영업 판정은 내부 제외 처리에만 사용하고 화면에는 표시하지 않습니다.
- 좌표가 없거나 잘못된 경우에는 이전 음식점 마커를 지우고 안내와 지도 검색 링크를 표시합니다.

추가한 `음식 종류`는 `업종정보` 값을 그대로 사용합니다. 한식·양식·중식뿐 아니라 카페·디저트, 야식, 기타도 원본 분류를 보존합니다. `음식 형태`는 `메뉴한글명`의 전체 메뉴를 하나씩 기존 분류 함수로 판정한 뒤, 중복 없이 합친 값입니다. 여러 형태는 `면 | 밥 | 구이`처럼 기록합니다. 전체 메뉴 목록이 없으면 대표메뉴를 확인하며, 어느 형태도 판정할 수 없으면 `미분류`입니다. 현재 미분류는 116행입니다.

`영업 시간대`는 요일별 추천 가능한 실제 시각을 저장합니다. 예: `월=휴무 | 화=11:00~15:00,17:00~21:00 | ...`. 여러 영업 구간을 쉼표로 나누고 휴게·재료준비 시간을 제외합니다. 라스트오더가 명시되면 그 시각부터 새 추천에서 제외합니다. 시작 시각은 포함하고 종료 시각은 포함하지 않습니다.

`월=17:00~익일02:00`은 월요일 영업 일정에 속하며, 화요일 01:00 조회에도 포함됩니다. 화요일 02:00부터는 제외합니다. 휴무와 미확인을 구별하며, 일부 요일이 불명확하면 그 요일만 미확인으로 기록합니다. 어느 요일에도 시간이 확인되지 않는 121행은 전체가 미확인입니다. 기존 47개 열의 값·행 순서·CP949 인코딩은 보존했습니다.

기본 조회는 `Asia/Seoul`의 현재 날짜·시각입니다. 사용자가 날짜나 시각을 입력하면 해당 일시를 사용합니다. 영업시간 적용 중에는 자료에서 영업 구간 포함이 확인되는 식당만 추천하고, 미확인 시간은 추천하지 않습니다. 현재시각 버튼은 자동 현재 시각 조회로 복원합니다. 시간 조건을 해제하면 808곳 전체가 다른 필터의 대상이 됩니다.

정기휴무는 `정기휴무=월#1,월#3`, 마지막 일요일만 영업하는 조건은 `영업조건=일#마지막`처럼 기록합니다. 공휴일·명절 예외도 분리하며, 한국 공휴일 자료는 python-holidays 0.108로 생성한 2020~2035년 달력을 사용합니다. 공휴일 예외가 있는 일정은 지원 연도 밖에서 미확인으로 처리합니다. 임시 공휴일의 추가나 영업 변경은 자료 갱신이 필요합니다. 추천은 CSV에 기재된 일정 기준입니다.

요일별 휴게·주문 마감·예외가 복잡한 행은 원문을 검토한 `business_hours_overrides.json`을 사용하며, 원문이 달라지면 이전 보정을 적용하지 않습니다. `python3 add_business_hours.py [입력CSV [출력CSV]]`로 같은 작업을 반복합니다. 출력 경로를 생략하면 입력 파일을 갱신합니다. 달력은 `korean_holidays.json`으로 제공되며 Java용 달력도 `BusinessHours.java`에 포함되어 있어 별도 라이브러리 없이 실행합니다.

`python3 tests/test_business_hours.py`로 날짜·자정·요일별 휴게·라스트오더·공휴일·정기휴무·원본 보존을 검증합니다. `node tests/time-browser.cjs`는 현재 한국 시각 기본값, 직접 날짜·시각 입력, 시간 조건 해제·복원, 기존 가격 필터와 교집합을 검증합니다. `tests/verify.py`는 실제 808곳에 대해 날짜·시각 조합 56,560건의 Python/Java 판정 일치도 확인합니다.

`AddFoodColumns.java`는 CSV의 종류·형태 열을 다시 작성하는 별도 도구이며, 웹 검색과 같은 메뉴 해석·형태 연결 규칙을 사용합니다. `javac -encoding UTF-8 -d build RandomFoodPicker.java BusinessHours.java GeminiFoodRecommender.java FoodPickerWeb.java AddFoodColumns.java`로 컴파일한 뒤 `java -cp build AddFoodColumns [입력CSV [출력CSV]]`로 실행합니다. 출력 경로를 생략하면 입력 파일을 갱신하며, 이미 있는 종류·형태 값도 다시 작성합니다. 기존 45개 열과 행 순서는 보존합니다. 웹 프로그램을 실행하는 것만으로 이 도구가 동작하지는 않습니다.

CSV 파일·포트를 바꾸려면 명령 프롬프트에서 다음과 같이 실행합니다. 인자를 생략하면 위 기본 파일, MS949, 8000 포트를 사용합니다.

```bat
start.bat "다른음식점.csv" 8001
```

웹 프로그램의 필수 열은 `음식점아이디`, `음식점명`, `대표메뉴명`, `음식 종류`, `음식 형태`이며, 지도 표시에는 `위도`, `경도`, 시간 검색에는 `영업 시간대`가 필요합니다. 원본 데이터와 동일한 한글 헤더를 사용하세요.

이미 PC에 이전 파일을 저장했다면, 서버를 `Ctrl+C`로 종료한 뒤 같은 폴더에서 `remove-confirmed-closed.ps1`의 내용을 PowerShell로 실행하면 됩니다. 이 스크립트는 CSV에서 폐업 확정 행을 삭제하고 기존 `RandomFoodPicker.java`에 같은 제외 처리를 추가합니다. 로컬 CSV는 CP949, Java는 UTF-8로 저장하고, 유지한 행의 모든 열 값과 순서를 보존합니다. 이후 Java를 다시 컴파일하고 서버를 시작하세요.
