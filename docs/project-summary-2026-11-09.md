# 밥픽(BOB Pick) 프로젝트 정리

정리 기준: 2026년 11월 9일, 한국 시간. 대화에서 확정한 요구사항과 현재 저장소의 구현을 기준으로 작성했습니다. 이 문서는 대화 원문 대신 결정 사항·구현 결과·확인 범위를 정리한 자료입니다.

## 1. 프로젝트 개요

대전 둔산동 음식점 데이터에서 사용자의 예산, 음식 종류, 음식 형태, 방문 일시에 맞는 음식점과 메뉴를 추천하는 웹 서비스입니다. 수동 랜덤 추천과 AI 대화 추천을 제공하고, 선택한 음식점의 위치·길찾기를 연결합니다. 회원별 메뉴 찜, 커뮤니티, 음식점 정보 수정·등록·홍보 신청과 관리자 검토 기능까지 구현했습니다.

## 2. 데이터와 추천 기준

- 입력 CSV: `관내 음식점 텍스트 데이터셋_둔산동_재검토_2.csv`
- 현재 보존된 CSV: 음식점 808행, 48개 컬럼, CP949 인코딩.
- 초기 DB 이전 데이터: 음식점 808곳, 메뉴 5,086개, 한국 공휴일 날짜 321건. 운영 중 승인한 새 음식점은 별도로 추가될 수 있습니다.
- 폐업이 확정된 데이터만 제외하고 미확정·미확인 자료는 유지합니다.
- CSV 원문 컬럼은 `restaurants.source_fields`에 보존하며 검색용 필드는 별도로 사용합니다.

### 음식 종류·형태

음식 종류는 CSV의 `음식 종류` 등록값을 사용합니다. 음식 형태는 CSV의 `음식 형태` 등록 범위와 개별 메뉴의 연결 규칙을 사용합니다. 대표 메뉴만 검사하지 않고 `메뉴한글명`의 전체 메뉴를 검색 대상으로 삼습니다. 음식 종류를 임의로 다른 기준으로 다시 바꾸지 않습니다.

형태·가격 조건은 같은 메뉴에서 모두 일치해야 합니다. 예를 들어 미향일식(음식점 ID 15779)의 대구탕은 국·탕·찌개 형태로 검색되며, 다른 메뉴의 가격을 대구탕 가격처럼 사용하지 않습니다.

### 가격

- 최소·최대 가격을 원 단위로 입력하며 경계 금액을 포함합니다. 비우면 해당 가격 제한이 없습니다.
- 가격 입력의 화살표 조정 간격은 1,000원입니다.
- 설명이 붙은 고정 금액은 숫자를 해석합니다. 단, '변동가격'처럼 변동을 뜻하는 항목은 뒤에 숫자가 있어도 '변동가격'으로 표시합니다.
- 변동가격과 가격이 없는 메뉴는 숫자 가격 조건에서 제외합니다.
- 메뉴 수와 가격 수가 다르면 앞에서부터 순서대로 연결하고 부족한 뒤쪽은 '가격 표시 없음'으로 처리합니다.
- 태평소국밥의 메뉴 7개·가격 5개 자료가 이 처리의 실제 검증 사례입니다.

### 영업시간

기본값은 한국 현재 날짜·시각입니다. 직접 입력한 방문 일시도 조회할 수 있습니다. CSV의 `영업 시간대`에서 요일별 영업 구간, 휴게시간, 주문 마감, 익일 영업, 정기휴무와 공휴일 예외를 판정합니다. 시작은 포함하고 종료는 제외합니다.

시간 조건을 적용할 때 영업 구간이 확인되지 않는 자료는 추천하지 않습니다. 시간 조건을 해제하면 다른 조건에 따라 검색합니다. 자동 시각 갱신은 이미 고른 추천 카드·고정·지도 마커를 지우지 않습니다.

## 4. 지도와 위치 처리

가게 좌표가 있으면 검증한 위도·경도로 네이버 길찾기 목적지를 연결합니다. 직접 좌표를 전달하는 목적지는 SIMPLE_POI 형식을 사용합니다. 좌표가 없거나 잘못되면 가게 이름·주소 검색으로 연결합니다.

출발지에는 임의 좌표를 넣지 않습니다. 브라우저 위치 API만으로 GPS·Wi-Fi 등 측정 출처를 확정할 수 없어, 추천·길찾기에서 사용자의 출발지를 자동 입력하지 않습니다. 위치 확인용 진단 화면은 추천과 분리되어 있습니다.

사이트 안의 지도 표시에는 네이버 클라우드 Maps의 운영 도메인 등록이 필요합니다. 사용자가 이 설정을 당장 진행할 수 없다고 하여 보류한 상태이며, 코드 적용과 지도 인증 완료는 구분합니다.

## 5. 시스템 구성

```text
사용자 브라우저
  └─ Vercel: HTML/CSS/TypeScript/JavaScript 웹 화면
       ├─ Supabase Auth: 회원·로그인
       ├─ Supabase PostgreSQL/RPC: 메뉴·추천·찜·게시글·신청·관리자 처리
       └─ Supabase Edge Function: AI 요청과 후보 검증
            └─ Gemini API

추천 카드 → 네이버 길찾기
웹 지도 → Naver Maps JavaScript SDK
```

Supabase 프로젝트 이름은 BOB-Pick, 참조 ID는 `rllfxdybuncooswotccs`입니다. Vercel 프로젝트는 `aaidan02/bob-pick`입니다.

### 회원 공통키와 권한

회원 공통키는 `auth.users.id` UUID입니다. `profiles.id`, `favorites.user_id`, `posts.user_id`, `requests.user_id`, `request_reviews.reviewer_id`, `change_logs.actor_id`가 이를 참조합니다. 음식점과 메뉴는 회원과 독립적이며 메뉴는 음식점 ID를 참조합니다.

회원의 찜·신청은 본인 또는 허용된 관리자만 조회합니다. 게시글 수정은 작성자만, 삭제는 작성자 또는 관리자만 가능합니다. 관리자 자격은 `private.admin_members`와 서버 함수로 확인하며 화면 버튼만으로 권한을 결정하지 않습니다.

관리자 검토는 음식점 정보 반영·처리 기록·이력을 하나의 트랜잭션으로 저장하고 중복 처리를 막습니다.

### API 키

이전 Java 버전은 실행할 때마다 터미널에서 Gemini 키를 입력받았습니다. 현재 배포 버전은 Supabase Edge Functions의 Secrets에 `GEMINI_API_KEY`를 저장해 서버에서 사용합니다. 브라우저나 웹 소스에는 비밀 키를 넣지 않습니다.

AI 추천은 로그인 후 사용하며 계정별 하루 20회 제한이 있습니다. AI가 반환한 음식점·메뉴 ID는 실제 DB 후보와 다시 비교합니다.

## 7. 주요 오류 해결

| 문제 | 원인·조치 |
| --- | --- |
| Java 클래스를 찾지 못함 | 컴파일 출력 위치와 실행 classpath를 맞추고 build 기준 실행 방법 정리 |
| PowerShell bobPickJdk 오류 | 변수 이름 앞의 `$` 누락과 명령 입력 방법 확인 |
| 한글 깨짐 | Java 소스·웹 UTF-8, CSV CP949, 터미널 출력 인코딩을 구분 |
| 추천 메뉴가 사라짐 | 현재 시각 자동 갱신·후보 수 갱신이 추천을 지우지 않도록 분리 |
| AI 대기 후 오류·검색 혼동 | 수동/AI 동작 분리, 요청 단계·오류·응답 순서 처리 보완 |
| 태평소국밥 가격 해석 실패 | 변동 표시 우선, 메뉴·가격 순서 연결, 누락 가격 표시 적용 |
| 길찾기 목적지 연결 실패 | 좌표 검사와 SIMPLE_POI 형식 적용, 좌표 없으면 가게 검색으로 연결 |
| 관리자·문의 내역의 object is not iterable | 일대일 처리 결과를 배열로 읽던 부분을 객체/null 처리로 수정 |
| 관리자에게 다른 사람 글 삭제 버튼 없음 | 관리자용 삭제 UI 추가, 작성자 ID 필터를 제외하고 DB 권한 검사 유지 |
| 제목만 눌러야 글을 볼 수 있음 | 게시글 줄 전체가 열리는 details/summary 구조로 변경 |

## 8. 검증과 배포 기록

최근 구현 버전에서 웹 빌드, DB·권한·길찾기 테스트 15개, 브라우저 시나리오 10개를 통과했습니다. 영업시간은 기존 Java와 SQL을 24,420개 조건으로 비교했습니다. 최종 코드의 GitHub Actions push·PR 검사도 통과했습니다.

브라우저 검증은 로컬 Auth/PostgREST 대역과 PostgreSQL 엔진을 연결한 방식입니다. 처리 결과가 객체로 오는 관계를 대역에도 반영했고, 일반 회원의 다른 사람 글 수정·삭제 차단과 관리자 삭제를 확인했습니다.

최종 운영 배포는 Vercel READY 상태와 `https://bob-pick.vercel.app`의 HTTP 200·새 빌드 파일 반영을 확인했습니다. 실제 Gemini 응답, 이메일 전달, 네이버 지도 인증과 휴대폰 위치 수신은 자동 테스트 통과와 별도로 운영 환경에서 확인할 항목입니다.

## 9. 남은 확인 사항

1. 네이버 클라우드 Maps의 Web 서비스 URL에 운영 주소를 등록하고 실제 지도 표시 확인.
2. 실제 회원 계정으로 가입 확인 메일·비밀번호 재설정·메뉴 찜 재접속 확인.
3. Supabase Secrets의 Gemini 키로 실제 채팅 추천 응답과 모델 사용 가능 여부 확인.
4. 실제 휴대폰에서 HTTPS 접속·하단 메뉴·길찾기·별도 위치 진단 확인.
5. 운영 데이터와 영업시간 변경 시 갱신 절차 정리. 추천 자료를 실시간 수집하는 기능은 구현 범위에 포함되지 않습니다.

회원·찜·커뮤니티·관리자 기능은 현재 구현된 상태입니다. 위 항목은 추가로 만들어야 할 기능 목록과 구분한 운영 확인 사항입니다.

## 10. 함께 제공하는 파일

- `development-history-2026-11-09.txt`: 초기 Java 통합부터 최신 UI·권한 수정까지의 진행 과정과 결정 이유. Windows 메모장용 UTF-8 BOM·CRLF.
